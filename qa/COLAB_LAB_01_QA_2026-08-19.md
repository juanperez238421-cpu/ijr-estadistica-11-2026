## Registration policy after patch

- Valid group remains required: `11A`, `11B`, or `11C`.
- Any non-empty name can start the activity.
- If the name uniquely matches the institutional roster, `student_registry_id` is retained and the attempt remains connected to that student.
- If it does not match, `student_registry_id = NULL`, the typed name is stored exactly as `student_name_snapshot`, and the attempt is marked `is_roster_match = false`.
- Free-name attempts are de-duplicated by activity + group + normalized entered name.

## Fullscreen policy after patch

The browser Fullscreen API cannot physically disable the operating-system Escape key, Alt+Tab, task switching, another device, or browser chrome behavior. Therefore the enforceable policy is:

1. The student must enter fullscreen before registration starts.
2. Checkpoint submission is disabled outside fullscreen.
3. Any observable fullscreen exit pauses the portal with a modal gate.
4. The student must explicitly press `Volver a pantalla completa` to continue.
5. The Colab button arms an authorized external transition and reuses the same named Colab window.
6. On return from Colab, the portal re-enforces fullscreen.
7. Observable non-authorized leaves/fullscreen exits are logged and shown in the master dashboard.
8. Unsupported browsers are blocked from starting and instructed to use desktop Chrome/Edge.

This is stronger and technically more accurate than claiming that a web page can make leaving fullscreen impossible.
